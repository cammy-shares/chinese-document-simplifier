# 保真验收

按原文中的信息选择核对项，不向用户输出整张检查表。

| 风险 | 需要保留 | 常见错误 |
| --- | --- | --- |
| 数字边界 | 数字、单位、包含关系、范围 | 把“不超过 20 MB”改成“小于 20 MB” |
| 条件和权限 | 谁满足什么条件后可以做什么 | 删掉“管理员启用后” |
| 否定和例外 | 不能做的事、适用例外 | 把“暂不支持”改成“支持” |
| 不确定性 | 可能、倾向、预计、尚未确认 | 把“可能重试”改成“会自动重试” |
| 责任和因果 | 原文给出的主体与原因 | 把现象擅自归因为网络或人员 |
| 观点和证据 | 作者立场、取舍及证据强弱 | 把“我认为值得试”改成“已验证有效” |

## 边界案例

- “清楚的原文”：允许完全不改；改动量不作为质量指标。
- “每次最多 3 个附件”：不能改成每日额度。
- “失败的上传可能重试”：不能扩大成所有上传或保证成功。
- “重试间隔不详”：标记待确认，不填入常见的 5 分钟。
- “用户未提供具体动作”：指出缺失，不把抽象词硬替换成虚构功能。
- “引用、命令、字段”：除非明确要求修改，保持逐字一致。

## 何时提问

信息缺失若只影响一个局部，先完成其余正文并标记待确认。
如果读者身份或关键条件会使含义相反，先问一个必要问题。
不要求用户在普通改写前填写完整的写作简报。

## 验证限制

文件结构验证不能证明模型遵守这些规则。
维护者应使用未提供标准答案的真实请求复核，并检查事实是否保留。
本项目当前附带的是人工编写的虚构案例，尚无独立模型对照评测结果。
